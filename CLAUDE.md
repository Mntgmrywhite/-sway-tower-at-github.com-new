# Sway Tower

One-tap stacker for the browser (later wrapped for iOS with Capacitor). A block slides back and forth; tap to drop it; overhang is sliced off. The twist: the tower sways more as it gets taller, so a good drop means timing both the slider and the sway.

The prototype exists to answer one question: **does sway make it more fun, or just more random?**

## Commands

Node lives in `~/.local/node` (user install). If `node` is not on PATH: `export PATH="$HOME/.local/node/bin:$PATH"`.

- `npm run dev` — dev server (with `--host`, so a phone on the same Wi-Fi can open the LAN URL)
- `npm run test` — Vitest, run once
- `npm run typecheck` — `tsc --noEmit`
- `npm run lint` — ESLint
- `npm run check` — typecheck + lint + test; run before every commit
- `npm run build` — typecheck, then static bundle to `dist/`
- `npm run preview` — serve the built bundle
- `npm run snap -- <skinId> [width] [height] [songTime]` — render a skin offscreen to `preview/<skin>-{start,climb,high,topple,blast,debris,over,hard,hardClimb,hardFall,hardBlast,fireworks,fireworksLate,shockwave,confetti,confettiLate,popcorn,bars}.png` (the hard* shots are Drop; fireworks … popcorn are the other blasts) (fallback fonts; look at them with an image viewer). Use this to check visual work. `songTime` draws the shots as if the music were that many seconds in (for scenery that keeps time with the music).
- `npm run build:artifact` — build, then inline everything except the songs into `dist/sway-tower.html` for publishing as the claude.ai Artifact (https://claude.ai/artifact/1iy2tocHgvV3jfE1CLE9v3); the songs (together over the 16 MB page limit) go to `dist/music/<hash>.mp4`, fetched by the page. Republish that file with those files (`dist/artifact-files.json` maps each published path to its file) to keep the same link. The iOS app keeps everything inline.
- `npm run ios` — build, then copy the bundle into the iOS app (`cap sync ios`); build and run it from Xcode (`npm run ios:open`) or with `xcodebuild -project ios/App/App.xcodeproj -scheme App`
- `npm run ios:art` — redraw the placeholder app icon and launch image (`scripts/ios-art.ts`)

## Stack

Vite + TypeScript (strict) + Canvas 2D. No framework, no physics engine, no runtime dependencies.

**iOS app:** Capacitor 8 (`capacitor.config.ts`, native project in `ios/`, Swift Package Manager, no CocoaPods). The only runtime packages are Capacitor's (`@capacitor/core`, `haptics`, `preferences`), all bundled. The app's own plugin is `ios/App/App/NativePlugin.swift` (registered in `SceneDelegate.swift`; `src/native/native.ts` is its JS side: the App Store review prompt, opening the store page in Safari, Game Center and the share sheet; every call is a quiet no-op on the web). `PrivacyInfo.xcprivacy` is the privacy manifest (no tracking; UserDefaults only for the saves), `App.entitlements` holds the Game Center entitlement, `ITSAppUsesNonExemptEncryption` is false, and `MARKETING_VERSION` must equal package.json's version (the Settings sheet shows that one; `src/version.test.ts` checks they agree). The owner's hand-off steps live in `store/IOS-CHECKLIST.md`. The app is portrait-only and full screen: no status bar, home indicator hidden (`Info.plist`, SystemBars in `capacitor.config.ts`), bottom-edge swipes deferred to the game (`GameViewController` in `SceneDelegate.swift`). It must work offline: fonts (`src/fonts.ts`, Fontsource files inlined like the audio) and audio ship inside the bundle; never load anything from the network. The build stays one JS file (`codeSplitting: false`). `src/haptics.ts` plays the haptic cues on the Taptic Engine natively (navigator.vibrate on the web). Saves: `src/storage.ts` mirrors every `sway-stack:*` localStorage key to Preferences, and `GameViewController` puts lost keys back before the page loads, so iOS purging the web view's storage loses nothing (never `location.reload()` in the app: WKWebView then reports zero safe-area insets).

## Architecture

- `src/game.ts` — pure game logic: state, `step(state, dt)`, `drop(state)`. No DOM, no canvas, no randomness, no `Date.now()`. Everything deterministic so it can be unit-tested and driven by a bot.
- `src/config.ts` — every tunable number lives here. Fixed values are `const`s; playtest knobs live in the mutable `tuning` object (defaults in `DEFAULT_TUNING`). Logic must read `tuning.*` at call time, never cache it. No magic numbers in logic or rendering.
- `src/panel.ts` — on-screen tuning panel (⚙ top-right). Edits `tuning` live, persists to localStorage, pauses the game while open.
- **Two styles + skins.** The default look is bright **2D cartoon** (reference: a Flappy-Bird-like night scene: periwinkle sky, faded distant silhouettes, puffy cel-shaded teal clouds piled at the sides, ink-outlined objects up close, grass lip over stone tiles). The pure **Neon** look (Far Cry Blood Dragon: grid floor, striped sun, glowing bars, scanlines) is kept as its own style — never delete it. Skins pick a style; holiday skins are cartoon.
  - `src/base/draw.ts` — shared helpers: `outlined` (fill + ink outline: the standard cartoon look), `ink`, `inkedLine` (bones, branches), `outlinedText`, `mix`/`alpha`, `circle`/`oval` (each starts its own subpath — never put several arcs in one path without them, or the canvas joins them with stray lines), `roundRectPath`, `hash`, `emerge`. The `neon*` helpers are for the Neon style only.
  - `src/base/world.ts` + `blocks.ts` — cartoon world (sky + stars, moon, faded skyline, cloud bank, height clouds, mown field from `horizonY`, grass-and-tiles foreground) and the cartoon bar (chunky toy block: bevels on all sides, ink outline, inked symbols — never a capsule). Exports `layerGround`, `fieldY(scene, z)` (z = `TOWER_DEPTH` is the tower's line), `altitude01`, `puffs`, `moon`.
  - `src/base/neon-world.ts` + `neon-blocks.ts` — the Neon style's world and bars.
  - `src/base/style.ts` — `kitFor(skin)`: the one place that maps a skin's style to its world, bars, HUD text, lives and game-over card. The renderer never branches on style.
  - `src/skins/skin.ts` — `Skin = CartoonSkin | NeonSkin` (discriminated by `style`). Cartoon palette: sky stops, star, moon, cloud shadow/base/light, far, field far/near, grass/grassDark, stone/stoneLight, ink. HUD: display font, title, ui, accent, life. Optional layers: `celestial`, `sky`, `far` (faded silhouettes standing on `horizonY`, behind the cloud bank), `ground` (props on the field), `foreground` (after the base tiles). `paintsBackdrop: true` (every cartoon skin but Halloween and New Year's) says the ground hook paints the whole screen behind the tower, so the base world skips its sky, cloud bank, heights and field (about 4.5 ms a frame on a phone). `fonts` (Google Fonts, loaded on demand), `dates` for auto-pick.
  - `src/skins/index.ts` — registry (Classic first = fallback, then Toy Kingdom, the Neon pair, then holidays in calendar order from the autumn), `skinForDate`, `resolveSkin`. A skin's season is `dates` (fixed [month, day] windows) or `datesFor(year)` for one that moves: Mardi Gras's is the six days up to Fat Tuesday (`src/skins/easter.ts` computes Easter and the 47 days back), February 14 left to Valentine's. The first skin whose season holds the date wins, so Mardi Gras is registered before Valentine's. `tuning.skin` is "auto" or an id; Options button (top-left) and the ⚙ panel both pick it.
  - `src/skins/<id>.ts` (+ optional `src/skins/<id>/` folder) — `classic` (Sky Islands, the default), `toyblock` (Toy Kingdom), `neon` (Synthwave), `neon-cyber` (Cyberpunk), `halloween`, `thanksgiving`, `christmas`, `newyear`, `mardigras` (Mardi Gras), `valentines` (Valentine's Day), `stpatricks`, `july4` (Independence Day), `oktoberfest`. Scenery that keeps time with the music reads `s.songTime ?? NaN` and its song's cues from `src/audio/music/manifest.json`, and runs the same cycle on scene time when no music plays (New Year's countdown: `src/skins/newyear/countdown.ts` + `marquee.ts`; Synthwave's car: `src/skins/neon/car.ts`). `src/skins/glyphs.ts` — geometric symbols shared by Classic and Neon.
  - `src/preview/shots.ts` — deterministic game moments shared by `npm run snap` and the render smoke test.
- **Cartoon art rules:** bright, saturated, high-contrast — readability first (the user found heavy neon impossible to see). Near things: flat fills, a light top / shaded bottom, ink outline (palette.ink). Far things: faded flat silhouettes, no outline. No glow-heavy effects, no dark muddy scenes. Bright flashes are for feedback moments (perfect drops), not the scenery.
- `src/camera.ts` — how world units land on the screen (`frameFor`); both modes are framed alike, Drop with one extra bar of headroom for its raised slider. A zoom-out and sideways pan (built for the retired no-slicing Hard, when towers leaned) remain behind `View.follow`, which nothing sets; the skins still support a zoomed view.
- `src/render.ts` — draws a state to a canvas via the active style kit: the world, the tower, the perfect-drop seam flash and gold tint, falling pieces, the slider, the PERFECT pop, the HUD (score, best, lives, perfect counter and the current run), the game-over card (with the medals just earned) and the title screen's logo. `addFlash` (a perfect: flash + pop), `addFalling` (a cut) and `addTopple(view, state, side)` (the game-over topple and blast) are what main.ts feeds it; `render(…, songTime)` passes the music position on as `Scene.songTime`. Cosmetic-only effects (falling pieces, flash, pop, camera easing) live here and in `src/fx/`, never in logic.
- `src/fx/` — renderer-only feedback: `pops.ts` (the PERFECT pop: "PERFECT ×n" on a streak, a little bigger as the streak grows; a new pop cuts the older one short so words never stack; it never rises into the HUD) `falling.ts` (cut pieces tumbling away), `topple.ts` (game over, both modes: the top 8 bars swing over about their bottom corner toward the side of the last miss, then blow up at 0.5 s into chunks flung that way with a shake of the scene (not the HUD; none with reduced motion); the card comes at `TOPPLE_TIME` 1.3 s. Five blasts, one per run from `blastVariant(state, dir)` (an integer hash of the score, perfects, mode, side and the tower's shape, so the same run always ends the same way): `starburst` the fireball, `fireworks` a chrysanthemum of glittering sparks with the bars as streaks and a second bloom, `shockwave` two rings racing out with whole bars pinwheeling away and a mushroom of smoke, `confetti` the bars crumbling into squares and streamers that float down, `popcorn` three little pops up the swinging section at 0.26/0.34/0.42 s and then the starburst; each with its own sound (`BLAST_SOUND` in `src/audio/sounds.ts`, cued at `blastCueAt`: popcorn's at its first pop, the heavy haptic still at the blast) and `blast.ts` (the shapes, not the variants: burst, smoke, sparks, streaks, rings, flares, confetti, streamers and the flash, per style through `StyleKit.blast`: cartoon fire and party colors with ink and puffy smoke, neon rays and rings). Deterministic from the drops and the dt they are fed.
- `src/main.ts` — wiring: canvas sizing, input, RAF loop, the title → run → game-over flow (`flowStep` in `src/title.ts`), the mode (`sway-stack:mode`) and each mode's best (`sway-stack:best` for Slide, `sway-stack:best:hard` for Drop, kept in memory too), Drop's landings (the sound, haptic, flash and next bar come at contact), each drop's sound (`src/audio/sounds.ts`) and haptic (`dropHaptic` in `src/haptics.ts`), achievements, the skin's song (`skinSong`), the music's tempo (`audio.setTempo(musicTempo(state))` every frame) and position (`audio.position()` → `Scene.songTime`), the settings (`src/settings.ts`: haptics on/off and reduce motion auto/on/off, resolved every frame into `RenderOptions.still` and a mark on the page the sheets' CSS reads), what a screen reader hears (`src/announce.ts`: each landing's score in a few words through a throttled live region), the share card (`src/share.ts`), the review ask (`src/native/rate.ts`) and Game Center (`src/native/gamecenter.ts`).
- `src/title.ts` (+ `title.css`) — the title screen: the skin's start scene with the logo drawn on the canvas (`titleLayout()` in render.ts) and DOM controls over it, styled per skin: Slide / Drop cards with each best, one big PLAY (Space/Enter), and small Skins (the Settings sheet), Medals and Sound buttons. The game-over card adds a row under it: Share (the final tower as a 1080×1920 picture with the score and a line of text, through the iOS share sheet or the Web Share API; hidden where neither can share a picture) and Menu (Escape) back to the title. Pure flow logic (`flowStep`, `keyIntent`, `tapIntent`) is unit-tested.
- `src/options.ts` (+ `options.css`) — the Settings sheet (the title's Skins button, and the ⚙-less Settings button top-left during a run): Mode (Slide / Drop), Sound (music, effects, haptics: the haptics switch only where the device has a motor), Motion (reduce motion auto / on / off), in the iOS app a Game Center row (who is signed in, Sign in, the mode's leaderboard), the skin picker, and a footer with the version, Credits and, in the app, Rate Sway Tower. `src/credits.ts` (+ `credits.css`) — the Credits sheet: by Turk White, the CC0 libraries the songs are rendered from, the fonts and their licenses (`public/font-licenses.txt`, which the OFL requires to ship). `src/sheet.ts` — what the sheets share: the focus trap, Tab wrapping, arrow keys on a radio row. `src/contrast.test.ts` checks every skin's sheet and title text against WCAG AA; `src/achievements-sheet.ts` gets a See in Game Center button once signed in.
- `src/native/` — the iOS app's extras, all no-ops on the web: `native.ts` (the plugin bridge, `APP_STORE_ID` empty until the App Store Connect record exists, `APP_VERSION`), `rate.ts` (the review ask: on the game-over card after a new best, from the third run on, at most once per app version; `sway-stack:rate`), `gamecenter.ts` (a leaderboard per mode and the medals as achievements with the same ids; sign in quietly once after the first PLAY, never on launch; a decline is remembered in `sway-stack:gamecenter` and Settings offers Sign in instead; every sign-in resubmits each mode's best and every medal; every game over submits the score; the access point shows on the title only). `src/share.ts` — the share card and text (`SHARE_LINK` empty until there is a store or landing page).
- `src/achievements.ts` — the medal ladders and their save (`sway-stack:achievements`, mirrored to iOS like every `sway-stack:*` key; damaged saves keep their valid parts). `achievements-sheet.ts` + `achievements.css` — the Medals screen; `medals.ts` — medal art (canvas and SVG).
- Tests sit next to code as `*.test.ts`. The bot test proves the game is beatable with perfect timing.

## Identity

- Name: **Sway Tower**. Sway is the hook and the reason the game exists; keep it front and center.
- Developer and copyright: **Turk White** (the Credits sheet, the store listing, the landing page and the press kit).
- **Classic (the default skin) is Sky Islands:** the tower grows from a small floating island (grassy cap; underside of wavy soil bands with hanging roots and vines — our signature motif) and climbs into the sky: meadow far below, into the clouds, past drifting islands (one spilling a cloud waterfall), through a sunset, into a starry night. Height tells the story; the scenery stays calm so the tower reads first. That image is the game's signature. The owner confirmed it as the default over Toy Kingdom (2026-10-16), which stays a skin anyone can pick; the iOS app icon and launch image (`npm run ios:art`) show it.
- **Simple is the point** (the owner, after playtesting; "Retro Bowl succeeded because it is simple to pick up"): build as high as you can. The game opens on a title screen (logo, PLAY, Slide / Drop with each best, Skins, Medals, Sound). While stacking, the screen shows only the scene, tower, slider, falling pieces, the PERFECT word with its flash, and score/best/lives/perfect count. No explanatory overlays, gauges or tutorial text; medals earned mid-run get only a soft chime and appear on the game-over card.
- **In good taste, rated 12+** (the owner, 2026-10-20: "if anything seems in bad taste or not kid friendly, let's remove it", then, since Halloween's Headless Horseman, skeletons and ghouls already set the rating: "we can just have the 14+ rating" — Apple's tiers are 4+, 9+, 12+ and 17+, so declare mild horror and mild alcohol references for 12+). Cheerful drinks are fine as scenery: Oktoberfest's steins, beer tent and barrel wagon, St. Patrick's green brew, New Year's champagne; Mardi Gras may have fun masks and skeleton floats. Still never: anything suggestive, drunkenness or rowdiness, a costume or caricature of a people (Thanksgiving's table is set by townsfolk in everyday autumn clothes), a real-person likeness, a brand. An MLK Day skin was built and dropped the same day as bordering on insensitivity (its song is in git history at be84b55, the stub at fa42026); don't bring it back.
- Stay clearly distinct from Ketchapp's *Stack*: no isometric 3D blocks, no pastel gradient backgrounds, no thin minimal score font, and don't lean on "stack" in the name. Bright, flashy, high-contrast visuals (neon is the current base).

## Skin art direction (decided by the owner)

Evoke each reference's setting, era, mood, palette and motifs — never copy copyrighted characters or distinctive designs (e.g. Sam from *Trick 'r Treat*, the Peanuts gang and Snoopy's doghouse, Henson's creatures, Disney's character styling). Public-domain sources are fair game: Dickens' *A Christmas Carol* (1843), Irving's *Legend of Sleepy Hollow* (1820), Fitzgerald's *The Great Gatsby* (1925). Use generic, our-own designs for real-world landmarks.

**Background styles (the owner, 2026-10-20: "the backgrounds are all blending together"):** each holiday skin's world gets its own graphic style, so no two read alike at a glance, while every approved action and story beat stays. Layering rules for all of them: the detail lives in the far and near layers; the midground stays simple (flat ground, a fence line, low-contrast trees); the center band behind the tower stays quieter and lower in contrast than the edges so play stays readable; pointillism only as a subtle texture (glowing dots for Christmas lights or Mardi Gras parade lights), never the main style. **And (the owner, 2026-10-21): every remaining skin "needs to be big bold, almost too wild to believe"** (the restyles still to come, Independence Day's pass, Valentine's at height and Toy Kingdom's rocket): spectacular, extravagant, surprising set pieces and vistas, never timid or modest, at New Year's level of craft (the quality bar for every skin); the wildness lives at the edges and in the far and near layers, and the tower's column stays calm and readable.

## Rules

- World units, not pixels: playfield is `WORLD_WIDTH` wide; the renderer scales to the screen.
- Sway must affect overlap in **world (screen) space**. The slider must not ride the swaying tower, or sway is cosmetic.
- Input is `pointerdown` (+ Space for desktop). No click delay, no scroll/zoom.
- `localStorage` access is wrapped in try/catch.
- Build in thin slices; one commit per working slice, with `npm run check` passing.

## Game rules (decided)

**Simple and fun, the original rules** (the owner's call: easy to pick up, like Retro Bowl). Build as high as you can. A later balance mechanic (lean, teeter, topple, LAST CHANCE, gusts, perfects that steady before they rebuild, slow motion, the topple fall) was removed for simplicity; it lives in git history (commit 495eeaa, spec in 17e381e). Don't bring any of it back without the owner.

- Sway = base wave scaled by height (perfect drops add no energy, but taller towers move more at the top) + a damped-spring "kick".
- A sloppy drop kicks the tower toward the overhang side, proportional to the overhang; the sway calms after the chop. Kicks change velocity only, never position, so the tower never jumps.
- Placed blocks never topple during play. Cut pieces fall visibly and tumble (cosmetic, renderer-only). The game ends with a topple and blast (renderer-only; see `src/fx/topple.ts`).
- Kick damping is capped at critical (an overdamped spring settles slower, so higher "decay" past that would feel worse).
- A perfect drop calms the tower: sway (base and kick) scales by `1 - perfectCalm * calm`, where `calm` eases to 1 for `CALM_TIME` then back to 0. Smooth, so no jumps. Shown with a seam flash and a gold tint on the block, the PERFECT word (PERFECT ×n on a streak), and a chime that climbs with the streak.
- Every slice is pushed onto `cuts`; each perfect drop pops the newest and wins it back on the tower edge that receded, so a run of perfects rebuilds a sliver to the exact original bar. Misses are not slices.
- A miss does not end the game: it costs one of `LIVES` (3); game over at 0.
- Haptics are for the good moments (the owner: "it should hit when you perfectly align the bars"): a perfect plays iOS's Success notification, every 5th perfect in a row adds a heavy tap, and the game-over blast gets a heavy thump with two lighter debris taps; ordinary drops and misses are silent (`dropHaptic` in `src/haptics.ts`). The Haptics switch in Settings silences them all (`settings.haptics`).
- `src/game.ts` stays deterministic: no `Math.random`/`Date.now` (lint rule).

### Modes (decided by the owner)

The owner's final word: "Both modes are the same, except one slides across the top of the pieces and the other does the exact same but spaced one bar apart, and then drops onto the top of the tower. These both have slices, and the same slower-to-fast speed." The player sees **Slide** and **Drop**; the internal ids stay `"normal"` and `"hard"` and every storage key is unchanged (bests, mode and medals carried over from the old Normal/Hard). Picked on the title screen (or the Options sheet), saved as `sway-stack:mode`; switching starts a fresh run; each mode keeps its own best. `newGame(mode)`.

- **Slide** (`"normal"`): the rules above, bit-identical to the shipped rules (`src/testing/shipped-game.ts` is a frozen copy, A/B-replayed in `src/normal-parity.test.ts`; re-freeze it only when Slide changes on purpose).
- **Drop** (`"hard"`): exactly Slide's rules and tuning (slicing, perfects that rebuild, 3 lives, the same slow-to-fast slider, sway, kicks and calm), with one difference: the slider runs one bar-height above the top bar (`DROP_GAP`), and a tap stops it and drops the bar, falling straight down (`DROP_GRAVITY`, about 0.27 s) while the tower keeps swaying; the landing (slice, perfect or miss) is judged at contact in world space against the swayed top bar. Taps during a fall are ignored; the sound, haptic, flash, PERFECT pop, sliced piece and next bar come at contact. A Drop run's start shows a small DROP under the name. Proof in `src/drop.test.ts` (with `src/testing/bots.ts`): Drop's landing equals Slide's drop at the moment of contact; a perfect-timing bot climbs hundreds of bars; a ±40 ms human does about as well as in Slide when reading where the top will be, worse when aiming where it is at the tap.
- **Every game ends in a topple and blast** (the owner: "it topples then blows up, depending on the side it topples towards"): on the miss that takes the last life, the top of the tower tips over toward that miss's side and blows up (see `src/fx/topple.ts`) in one of five ways (starburst, fireworks, shockwave, confetti, popcorn: the owner asked for "a few different explosions"; `blastVariant` picks one per run), each with its own synthesized sound (`src/audio/sfx/{boom,firework,shockwave,confetti,popcorn}.mp4`, `npm run sfx -- <name>`) and a heavy haptic at the blast; the music stays back until the card.
- **Music keeps pace with the bar in both modes, same pitch:** the owner: "music should not be sped up until you get closer to 40+ stacks". `musicTempo(state)` keeps the written tempo through bar `TEMPO_FROM_SCORE` (40), then climbs in proportion as the slider keeps speeding up, reaching `TEMPO_MAX` (1.35; the stretch loses drum hits past it) exactly when the slider reaches its cap (bar 77 at the default tuning); 1 on the title and after game over. `audio.setTempo` rounds it to semitone steps of speed (`src/audio/tempo.ts`), a Web Worker time-stretches the song's loop to that step (`src/audio/stretch.ts`, circular WSOLA, seamless; inlined into the bundle), and the switch lands on the next bar line at a point both versions play, with a 60 ms crossfade. No worker, a failed stretch or a song without loop points: the music stays as written.
- History: Hard was once "actual physics, no extra lives" (no slicing, center-of-mass topples, one life, everything "to 11", a zoom-out camera); the owner replaced it with Drop. It lives in git history (commits 1e86b50, 03b21f1).
