# Sway Tower

One-tap stacker for the browser (later wrapped for iOS with Capacitor). A block slides back and forth; tap to drop it; overhang is sliced off. The twist: the tower sways more as it gets taller, so a good drop means timing both the slider and the sway.

The prototype exists to answer one question: **does sway make it more fun, or just more random?**

## Commands

Node lives in `~/.local/node` (user install). If `node` is not on PATH: `export PATH="$HOME/.local/node/bin:$PATH"`.

- `npm run dev` — dev server (with `--host`, so a phone on the same Wi-Fi can open the LAN URL)
- `npm run test` — Vitest, run once
- `npm run typecheck` — `tsc --noEmit`
- `npm run lint` — ESLint
- `npm run check` — typecheck + lint + test; run before every commit
- `npm run build` — typecheck, then static bundle to `dist/`
- `npm run preview` — serve the built bundle
- `npm run snap -- <skinId> [width] [height] [songTime]` — render a skin offscreen to `preview/<skin>-{start,climb,high,over,hard,hardClimb,topple,toppled,bars}.png` (fallback fonts; look at them with an image viewer). Use this to check visual work. `songTime` draws the shots as if the music were that many seconds in (e.g. `npm run snap -- newyear 390 844 56` for the marquee countdown).
- `npm run build:artifact` — build, then inline everything except the songs into `dist/sway-tower.html` for publishing as the claude.ai Artifact (https://claude.ai/artifact/1iy2tocHgvV3jfE1CLE9v3); the songs (together over the 16 MB page limit) go to `dist/music/<hash>.mp4`, fetched by the page. Republish that file with those files (`dist/artifact-files.json` maps each published path to its file) to keep the same link. The iOS app keeps everything inline.
- `npm run ios` — build, then copy the bundle into the iOS app (`cap sync ios`); build and run it from Xcode (`npm run ios:open`) or with `xcodebuild -project ios/App/App.xcodeproj -scheme App`
- `npm run ios:art` — redraw the placeholder app icon and launch image (`scripts/ios-art.ts`)

## Stack

Vite + TypeScript (strict) + Canvas 2D. No framework, no physics engine, no runtime dependencies.

**iOS app:** Capacitor 8 (`capacitor.config.ts`, native project in `ios/`, Swift Package Manager, no CocoaPods). The only runtime packages are Capacitor's (`@capacitor/core`, `haptics`, `preferences`), all bundled. The app is portrait-only and full screen: no status bar, home indicator hidden (`Info.plist`, SystemBars in `capacitor.config.ts`), bottom-edge swipes deferred to the game (`GameViewController` in `SceneDelegate.swift`). It must work offline: fonts (`src/fonts.ts`, Fontsource files inlined like the audio) and audio ship inside the bundle; never load anything from the network. The build stays one JS file (`codeSplitting: false`). `src/haptics.ts` plays the haptic cues on the Taptic Engine natively (navigator.vibrate on the web). Saves: `src/storage.ts` mirrors every `sway-stack:*` localStorage key to Preferences, and `GameViewController` puts lost keys back before the page loads, so iOS purging the web view's storage loses nothing (never `location.reload()` in the app: WKWebView then reports zero safe-area insets).

## Architecture

- `src/game.ts` — pure game logic: state, `step(state, dt)`, `drop(state)`. No DOM, no canvas, no randomness, no `Date.now()`. Everything deterministic so it can be unit-tested and driven by a bot.
- `src/config.ts` — every tunable number lives here. Fixed values are `const`s; playtest knobs live in the mutable `tuning` object (defaults in `DEFAULT_TUNING`). Logic must read `tuning.*` at call time, never cache it. No magic numbers in logic or rendering.
- `src/panel.ts` — on-screen tuning panel (⚙ top-right). Edits `tuning` live, persists to localStorage, pauses the game while open.
- **Two styles + skins.** The default look is bright **2D cartoon** (reference: a Flappy-Bird-like night scene: periwinkle sky, faded distant silhouettes, puffy cel-shaded teal clouds piled at the sides, ink-outlined objects up close, grass lip over stone tiles). The pure **Neon** look (Far Cry Blood Dragon: grid floor, striped sun, glowing bars, scanlines) is kept as its own style — never delete it. Skins pick a style; holiday skins are cartoon.
  - `src/base/draw.ts` — shared helpers: `outlined` (fill + ink outline: the standard cartoon look), `ink`, `inkedLine` (bones, branches), `outlinedText`, `mix`/`alpha`, `circle`/`oval` (each starts its own subpath — never put several arcs in one path without them, or the canvas joins them with stray lines), `roundRectPath`, `hash`, `emerge`. The `neon*` helpers are for the Neon style only.
  - `src/base/world.ts` + `blocks.ts` — cartoon world (sky + stars, moon, faded skyline, cloud bank, height clouds, mown field from `horizonY`, grass-and-tiles foreground) and the cartoon bar (chunky toy block: bevels on all sides, ink outline, inked symbols — never a capsule). Exports `layerGround`, `fieldY(scene, z)` (z = `TOWER_DEPTH` is the tower's line), `altitude01`, `puffs`, `moon`.
  - `src/base/neon-world.ts` + `neon-blocks.ts` — the Neon style's world and bars.
  - `src/base/style.ts` — `kitFor(skin)`: the one place that maps a skin's style to its world, bars, HUD text, lives and game-over card. The renderer never branches on style.
  - `src/skins/skin.ts` — `Skin = CartoonSkin | NeonSkin` (discriminated by `style`). Cartoon palette: sky stops, star, moon, cloud shadow/base/light, far, field far/near, grass/grassDark, stone/stoneLight, ink. HUD: display font, title, ui, accent, life. Optional layers: `celestial`, `sky`, `far` (faded silhouettes standing on `horizonY`, behind the cloud bank), `ground` (props on the field), `foreground` (after the base tiles). `paintsBackdrop: true` (Classic, Toy Kingdom, St. Patrick's) says the ground hook paints the whole screen behind the tower, so the base world skips its sky, cloud bank, heights and field (about 4.5 ms a frame on a phone). `fonts` (Google Fonts, loaded on demand), `dates` for auto-pick.
  - `src/skins/index.ts` — registry (Classic first = fallback, then Toy Kingdom, the Neon pair, then holidays), `skinForDate`, `resolveSkin`. `tuning.skin` is "auto" or an id; Options button (top-left) and the ⚙ panel both pick it.
  - `src/skins/<id>.ts` (+ optional `src/skins/<id>/` folder) — `classic` (Sky Islands, the default), `toyblock` (Toy Kingdom), `neon` (Synthwave), `neon-cyber` (Cyberpunk), `halloween`, `thanksgiving`, `christmas`, `newyear`, `stpatricks`. Scenery that keeps time with the music reads `s.songTime ?? NaN` and its song's cues from `src/audio/music/manifest.json`, and runs the same cycle on scene time when no music plays (New Year's countdown: `src/skins/newyear/countdown.ts` + `marquee.ts`; Synthwave's car: `src/skins/neon/car.ts`). `src/skins/glyphs.ts` — geometric symbols shared by Classic and Neon.
  - `src/preview/shots.ts` — deterministic game moments shared by `npm run snap` and the render smoke test.
- **Cartoon art rules:** bright, saturated, high-contrast — readability first (the user found heavy neon impossible to see). Near things: flat fills, a light top / shaded bottom, ink outline (palette.ink). Far things: faded flat silhouettes, no outline. No glow-heavy effects, no dark muddy scenes. Bright flashes are for feedback moments (perfect drops), not the scenery.
- `src/camera.ts` — how world units land on the screen (`frameFor`), and Hard's camera: the zoom-out (`zoomTarget`, down to `ZOOM_MIN` 0.6, easing out fast and back in slowly) that keeps a leaning or swinging top bar and the slider on screen, and the sideways pan once the base has left the view.
- `src/render.ts` — draws a state to a canvas via the active style kit: the world, the tower, the perfect-drop seam flash and gold tint, falling pieces, the slider, the PERFECT pop, the HUD (score, best, lives, perfect counter and the current run), the game-over card (with the medals just earned) and the title screen's logo. Zoomed (Hard), the world, tower and foreground are laid out on a virtual screen 1/zoom as big (same `u` and scale) and drawn shrunk; the HUD and the PERFECT pop keep their size, and `Scene.altitude` stays the unzoomed camera's so the zoom never moves a skin's story. `addFlash` (a perfect: flash + pop), `addFalling` (a cut) and `addTopple` (Hard: the tower tipped) are what main.ts feeds it; `render(…, songTime)` passes the music position on as `Scene.songTime`. Cosmetic-only effects (falling pieces, flash, pop, camera easing) live here and in `src/fx/`, never in logic.
- `src/fx/` — renderer-only feedback: `pops.ts` (the PERFECT pop: "PERFECT ×n" on a streak, a little bigger as the streak grows; a new pop cuts the older one short so words never stack; it never rises into the HUD) `falling.ts` (cut pieces tumbling away) and `topple.ts` (Hard: the slab above the failing interface swings about the contact corner, speeding up, and its bars peel off from the top into falling pieces; `TOPPLE_TIME` later the game-over card comes). Deterministic from the drops and the dt they are fed.
- `src/main.ts` — wiring: canvas sizing, input, RAF loop, the title → run → game-over flow (`flowStep` in `src/title.ts`), the mode (`sway-stack:mode`) and each mode's best (`sway-stack:best` for Normal, `sway-stack:best:hard`, kept in memory too), each drop's sound (`src/audio/sounds.ts`) and haptic (`dropHaptic` in `src/haptics.ts`), achievements, the skin's song (`skinSong`), and the music's tempo (`audio.setTempo(musicTempo(state))` every frame) and position (`audio.position()` → `Scene.songTime`).
- `src/title.ts` (+ `title.css`) — the title screen: the skin's start scene with the logo drawn on the canvas (`titleLayout()` in render.ts) and DOM controls over it, styled per skin: Normal / Hard cards with each best, one big PLAY (Space/Enter), and small Skins (the Options sheet), Medals and Sound buttons. The game-over card adds Menu (Escape) back to the title. Pure flow logic (`flowStep`, `keyIntent`, `tapIntent`) is unit-tested.
- `src/achievements.ts` — the medal ladders and their save (`sway-stack:achievements`, mirrored to iOS like every `sway-stack:*` key; damaged saves keep their valid parts). `achievements-sheet.ts` + `achievements.css` — the Medals screen; `medals.ts` — medal art (canvas and SVG).
- Tests sit next to code as `*.test.ts`. The bot test proves the game is beatable with perfect timing.

## Identity

- Name: **Sway Tower**. Sway is the hook and the reason the game exists; keep it front and center.
- **Classic (the default skin) is Sky Islands:** the tower grows from a small floating island (grassy cap; underside of wavy soil bands with hanging roots and vines — our signature motif) and climbs into the sky: meadow far below, into the clouds, past drifting islands (one spilling a cloud waterfall), through a sunset, into a starry night. Height tells the story; the scenery stays calm so the tower reads first. That image is the game's signature. The owner confirmed it as the default over Toy Kingdom (2026-10-16), which stays a skin anyone can pick; the iOS app icon and launch image (`npm run ios:art`) show it.
- **Simple is the point** (the owner, after playtesting; "Retro Bowl succeeded because it is simple to pick up"): build as high as you can. The game opens on a title screen (logo, PLAY, Normal / Hard with each best, Skins, Medals, Sound). While stacking, the screen shows only the scene, tower, slider, falling pieces, the PERFECT word with its flash, and score/best/lives/perfect count. No explanatory overlays, gauges or tutorial text; medals earned mid-run get only a soft chime and appear on the game-over card.
- Stay clearly distinct from Ketchapp's *Stack*: no isometric 3D blocks, no pastel gradient backgrounds, no thin minimal score font, and don't lean on "stack" in the name. Bright, flashy, high-contrast visuals (neon is the current base).

## Skin art direction (decided by the owner)

Evoke each reference's setting, era, mood, palette and motifs — never copy copyrighted characters or distinctive designs (e.g. Sam from *Trick 'r Treat*, the Peanuts gang and Snoopy's doghouse, Henson's creatures, Disney's character styling). Public-domain sources are fair game: Dickens' *A Christmas Carol* (1843), Irving's *Legend of Sleepy Hollow* (1820), Fitzgerald's *The Great Gatsby* (1925). Use generic, our-own designs for real-world landmarks.

- **Classic — Sky Islands:** our own style blending Flappy Bird's flat clarity, Sonic's saturated color and a tower climbing into the sky (the earlier Green-Hill castle was too close to Sonic and was replaced). Flat fills, one ink weight up close, faded far layers, two-tone shading, a tight palette; life (a kite, a hot-air balloon, birds, drifting clouds and islands) only in the side lanes, never behind the tower. Polished to the New Year's standard: a crafted home island (grass tufts, daisies, a glinting crystal, a spring falling into mist, a bluebird on the kite stake, a rope bridge to an islet with a birdhouse), a countryside far below (mountains, fields, a river, a village, a windmill), far islands on the cloud sea (a lighthouse whose beam turns at night, a great tree with lamps, a hamlet with a waterfall), lane life by hour (airship, cottage islands, paper plane, sky lanterns) and a night with an aurora and shooting stars. ## Rules

- World units, not pixels: playfield is `WORLD_WIDTH` wide; the renderer scales to the screen.
- Sway must affect overlap in **world (screen) space**. The slider must not ride the swaying tower, or sway is cosmetic.
- Input is `pointerdown` (+ Space for desktop). No click delay, no scroll/zoom.
- `localStorage` access is wrapped in try/catch.
- Build in thin slices; one commit per working slice, with `npm run check` passing.

## Game rules (decided)

**Simple and fun, the original rules** (the owner's call: easy to pick up, like Retro Bowl). Build as high as you can. A later balance mechanic (lean, teeter, topple, LAST CHANCE, gusts, perfects that steady before they rebuild, slow motion, the topple fall) was removed for simplicity; it lives in git history (commit 495eeaa, spec in 17e381e). Don't bring any of it back without the owner.

- Sway = base wave scaled by height (perfect drops add no energy, but taller towers move more at the top) + a damped-spring "kick".
- A sloppy drop kicks the tower toward the overhang side, proportional to the overhang; the sway calms after the chop. Kicks change velocity only, never position, so the tower never jumps.
- In Normal, placed blocks never topple. Cut pieces fall visibly and tumble (cosmetic, renderer-only).
- Kick damping is capped at critical (an overdamped spring settles slower, so higher "decay" past that would feel worse).
- A perfect drop calms the tower: sway (base and kick) scales by `1 - perfectCalm * calm`, where `calm` eases to 1 for `CALM_TIME` then back to 0. Smooth, so no jumps. Shown with a seam flash and a gold tint on the block, the PERFECT word (PERFECT ×n on a streak), and a chime that climbs with the streak.
- Every slice is pushed onto `cuts`; each perfect drop pops the newest and wins it back on the tower edge that receded, so a run of perfects rebuilds a sliver to the exact original bar. Misses are not slices.
- A miss does not end the game: it costs one of `LIVES` (3); game over at 0.
- Haptics are for the good moments (the owner: "it should hit when you perfectly align the bars"): a perfect plays iOS's Success notification, every 5th perfect in a row adds a heavy tap, and the run's end gets one heavy tap; ordinary drops and misses are silent (`dropHaptic` in `src/haptics.ts`).
- `src/game.ts` stays deterministic: no `Math.random`/`Date.now` (lint rule).

### Modes (decided by the owner)

The rules above are **Normal**. **Hard** is "actual physics, no extra lives, and the music speeds up in sync with the bar. Otherwise the same rules apply", then "harder, like all settings to 11" (the owner, after spamming to 131). Picked on the title screen (or the Options sheet), saved as `sway-stack:mode`; switching starts a fresh run. Each mode keeps its own best. No unlock gate. `newGame(mode)`; Normal is the default and stays bit-identical to the shipped rules (`src/testing/shipped-game.ts` is a frozen copy, A/B-replayed in `src/normal-parity.test.ts`; re-freeze it only when Normal changes on purpose).

- **No slicing, real balance:** an off-center bar keeps its full width where it landed (tower-local, like any placed bar), so bars never shrink and the slider always has the top bar's width. Each bar weighs in proportion to its width. After every placement, for each interface between bar i-1 and bar i, the combined center of mass of bars i..top must lie within their contact span (`balanceFailure(blocks)`); if not, the part above the **lowest** failing interface tips toward the side its center of mass passed: game over (the toppling bar doesn't score). The check uses rest positions, so sway alone never tips a tower; sway still moves where a drop lands in world space, exactly as in Normal. On screen: the slab swings about the contact corner and the bars peel off and fall (~1.2 s, no text), then the normal game-over card; a tap waits for the card.
- **One life** (`HARD_LIVES`): a drop with no overlap is a miss and ends the run.
- **Everything to 11** (all `HARD_*` in config.ts; the *_SCALE ones multiply the live tuning, so the ⚙ panel still moves Hard): the slider starts 1.5× faster, gains 3.5 per bar to 200 (about bar 37); sway 1.4× bigger, period 0.75×, full by bar 20; kicks 1.75× stronger, half the damping, full by bar 4, capped at 25 so a full swing still fits a 375-pt phone; the perfect window 1.25 (Normal 1.5; 1.0 skipped past 60 Hz frames); perfect calm 0.5× for 1.2 s. Seeded bots in `src/hard.test.ts` / `src/testing/hard-bots.ts` hold it to: spam dies early (random and fixed rhythms, a dense 40 ms–3 s rhythm scan: none reach 25), a perfect-timing bot climbs past 150, a good human (±40 ms) gets a median around 36. Re-run the dense scan whenever the period, damping or slider speed change: some combinations let a blind rhythm ride the kick resonance.
- **Same as Normal otherwise:** sloppy drops kick the sway by the overhang; a perfect snaps centered on the bar below, calms the sway, flashes, shows PERFECT (×n), chimes and buzzes (nothing to rebuild: nothing is sliced).
- **The camera zooms out** (the owner's choice over moving the scenery): when the top bar at the ends of its swing or the slider would leave the screen, the whole frame pulls back (down to 0.6) and eases back in; once the base has left the view the sideways pan takes over. Normal never zooms or pans.
- **Music keeps pace with the bar, same pitch:** tempo = clamp(slider speed / Hard's starting speed, 1, `HARD_TEMPO_MAX` 1.35; the stretch loses drum hits past 1.33) while a Hard run is played (`musicTempo(state)`); 1 in Normal and on the title and game-over screens. `audio.setTempo` rounds it to semitone steps of speed (`src/audio/tempo.ts`), a Web Worker time-stretches the song's loop to that step (`src/audio/stretch.ts`, circular WSOLA, seamless; inlined into the bundle), and the switch lands on the next bar line at a point both versions play, with a 60 ms crossfade. No worker, a failed stretch or a song without loop points: the music stays as written.
- The title screen shows both modes with their bests; a Hard run's start shows a small HARD under the name; while stacking nothing extra (one life dot).

### Achievements (decided by the owner)

"Stacks in groups of 5, 10, 15 … up to 100, and perfect runs in groups of 3, 6, 9 …": 20 stack medals (`stack-5` … `stack-100`) and 10 perfect-streak medals (perfect drops in a row in one run, `perfect-3` … `perfect-30`; raise `PERFECT_MAX` for more). Ids are stable for Game Center later. Either mode counts (the save keeps which mode earned each first); in Hard the toppling bar doesn't count. Old best scores credit their stack medals on first load. Earned mid-run: a soft three-note chime only (`unlockSounds`); the game-over card shows the new medals (up to 5, then +n); the Medals screen (from the title) shows the ladders with progress. Bronze, silver, gold up each ladder; stack medals are round coins, streak medals star-edged seals.

## Skin requirements from playtesting (decided)

- All skins: no prop may be cut off — not by the foreground band, not by the screen edges, not by another prop. Keep props fully on screen (or let them leave the view only by parallax as the camera climbs), and space them so they don't cut into each other. The only allowed clip is a body part emerging from the soil, and that edge must be hidden behind its dirt mound.
- Halloween graveyard: skeleton parts pop out **at random**. Each grave spot re-picks which part comes up (hand, skull, or feet) every cycle, and spots run on staggered, varying timings, so no two spots show the same part in lockstep and no spot always shows the same part. Deterministic from `scene.t` + `hash()` (cycle index × spot), never `Math.random()`.
- Halloween: no zombies, no ghosts in the sky, tombstones planted (base sunk into a mound), the mansion sits on its ground line, the jack-o'-lantern stands behind the tower, faces drawn with `circle`/`oval` so features never join. The crow on the RIP headstone flies (owner): every 9–29 s it takes off, climbs the left lane on the tower side of the kids and the porch house, circles the moon twice (only while the Horseman is off his ride) and lands again (`flight.ts`, `crow.ts`).
- **Height stories loop (all skins):** tall towers (a Hard spammer reached 131) never run out of story. After its first pass each skin repeats a loop segment forever (e.g. night → dawn → day → … → night), with everything keyed to height periodic and no visible seam: start level / period: Classic 30 / 128 (whole frames from 104), Toy Kingdom 104 / 130, St. Patrick's 104 / 132, New Year's 80 / 120, Halloween 120 / 120, Christmas 90 / 120, Thanksgiving 90 / 120, Synthwave 120 / 120, Cyberpunk 150 / 120. Each skin's `loop.test.ts` (or `story.test.ts`) checks periodicity, the seam and lanes over two loops, and levels up to 2000.
- **Zoom-out (all skins):** Hard's camera can draw a virtual screen up to 1/0.6 as big at the same `u`: every skin must fill it with nothing cut off (each skin's `zoom.test.ts`).

## Music (decided by the owner)

- Real instruments, never synth-sounding: songs are rendered offline from CC0 recordings in `~/APP/samples` (`PROVENANCE.json` there lists every source). Only CC0/MIT audio ships: no CC BY, GPL or non-commercial samples (App Store).
- One theme (`scripts/music/theme.ts`, a 6/8 waltz) with an arrangement per skin in `scripts/music/songs/<skin>.ts`; `npm run music -- <song>` renders `src/audio/music/<song>.mp4` + `manifest.json` (loop points). The theme must stay recognizable.
- **The owner's favorite instruments: saxophone, French horn, euphonium, piano and drums.** Feature them wherever they fit a skin's world. There is no CC0 euphonium: use `euphonium()` from `song.ts` (trombone + tuba on the same notes, mellowed).
- **Per-skin references (the owner's):** Classic = the waltz theme. Christmas = a symphonic-pops carol medley in the spirit of Leroy Anderson's *A Christmas Festival*, built on our theme, with our own order and links (public-domain carols only). Halloween = the waltz with spooky effects layered on it like *The Haunted Fun House* (werewolf howl, rattlesnake and hiss, creaking doors, chains, thunder, owls, a cackle). New Year's = a 1920s foxtrot/Charleston in the spirit of the *Jeeves and Wooster* theme (never its melody), a party crowd with clinks, corks and cheers, a ten-second countdown into "Auld Lang Syne" (cues `countdownStart`/`midnight` written to the manifest). Thanksgiving = an old-time string band in the spirit of Alisa Jones' hammered-dulcimer *Old Time Country Christmas* (the bowed/plucked psaltery stands in for the dulcimer). St. Patrick's = a pub-session set of jigs (whistle, fiddle, accordion, bodhrán, guitar). Toy Kingdom = a toy-box march in the spirit of Victor Herbert's *March of the Toys* (1903): a wind-up key and music box, a toy-piano march with snare and tuba, a horn-and-euphonium trio, a toy battle, a grandioso. Neon (Synthwave) = French electro in the spirit of Pyramid's *The Hall* EP. Cyberpunk = slow tech-noir in D minor (1980s tech-noir film scores): a real tenor sax on the theme over our synth bass, pads and gated drums, with rain and distant thunder. Each skin plays its own song by id (`skinSong`: else Neon for the neon style, else Classic). Sound effects never mask a melody.
- Synths: `scripts/music/synth.ts` is our own subtractive synth and drum machine. It voices the Neon and Cyberpunk songs and effects no CC0 recording covers (Halloween's werewolf howl, wind, snake hiss, rattlesnake and chains; Cyberpunk's rain); acoustic songs otherwise stay real instruments (Toy Kingdom's music box and toy-piano rods are our own tine patches, pending the owner's ear).
- The owner hears tuning and harshness ("a little sharp"): every recording is tuned (`autotune`, or a per-instrument `cents`), and the sampler tunes each note as heard at the pitch and length it is played, so songs never correct pitch themselves; bright leads get a `lowpass`. Check a song with `npx tsx scripts/music/mix.ts <song>` (ranges, per-phrase levels), `npx tsx scripts/music/tuning.ts <song>` (every note's pitch as heard; fails past ±5 cents on a favorite) and `npm run music:check -- <song>` (peak, loudness, seam).
